# گزارش مقایسه‌ای PHOENIX با پنل‌های رقیب

> تاریخ بررسی: اکتبر ۲۰۲۶ · مبنای بررسی: کد مخزن PHOENIX (مبتنی بر PHOENIX v3.3.1) + مستندات و انتشارهای عمومی رقبا
>
> رقبای بررسی‌شده: **پاسارگارد (PasarGuard)**، **PHOENIX (آپستریم MHSanaei)**، **پنل علیرضا (alireza0/x-ui)**، **مرزبان (Marzban)**، **novaX (NOVA-X-PANEL)** — به‌همراه اشاره‌ای کوتاه به Marzneshin، Remnawave و V2Board.

## ۱. PHOENIX امروز چه چیزی دارد؟ (خط پایه مقایسه)

### افزوده‌های انحصاری PHOENIX (چیزهایی که بیشتر رقبا ندارند)

| قابلیت | توضیح |
| --- | --- |
| **نمایندگی (Reseller) با کیف پول** | زیرحساب با لاگین جدا، اتصال صریح کلاینت/اینباند، کوتا، قیمت هر گیگ (`pricePerGb`)، موجودی/واریز (`balance`/`deposit`)، تراکنش‌ها و گزارش فروش — چیزی فراتر از «owner» سادهٔ Marzban/PasarGuard |
| **OpenVPN بومی** | دیمون per-inbound، گواهی per-client (CN=email)، فایل `.ovpn` آماده، ترافیک/آنلاین/کوتا در چرخهٔ عادی کلاینت |
| **L2TP/IPsec بومی** | strongSwan + xl2tpd/PPP، PSK ماندگار، همگام‌سازی `chap-secrets`، بازیابی پس از ری‌استارت، مدیریت فایروال UDP 500/4500/1701 |
| **AmneziaWG بومی** | کلیدسازی، پارامترهای AWG 3.1 (Jc/Jmin/Jmax/S1-S4/H1-H4/I1-I5 و...)، چرخهٔ کامل کلاینت، `.conf` و QR بومی |
| **Import/Export امن** | انتقال کلاینت/اینباند بدون از‌دست‌دادن داده، گزینهٔ صریح `replaceAttachments` |
| **آپدیت‌رسان PHOENIX-only** | همیشه آخرین ریلیز PHOENIX (هرگز سقوط به PHOENIX خام)، اعتبارسنجی باینری Xray قبل از جایگزینی، حفظ نسخهٔ قبلی برای rollback |

### ارث‌بری از PHOENIX v3.3.1 (که PHOENIX دارد)

پروتکل‌های VLESS / VMess / Trojan / Shadowsocks / WireGuard / Hysteria / MTProto + ترنسپورت‌های TCP، mKCP، WS، gRPC، HTTPUpgrade، XHTTP با TLS/XTLS/REALITY و Fallback · کلاینت‌ها با کوتا/انقضا/IP-Limit (fail2ban) + ریست دوره‌ای · نودها (چندسروری) · ساب (raw/JSON/Clash + تم‌های سفارشی + صفحهٔ اطلاعات) · ربات تلگرام (مدیریت ادمین، اطلاعات کلاینت، QR/لینک، IPها، بکاپ دیتابیس، اعلان ورود، آستانهٔ CPU، اعلان اتمام) · REST API با توکن · احراز هویت دومرحله‌ای (TOTP) · WARP · روتینگ/بالانسر/زنجیرهٔ خروجی · SQLite/PostgreSQL · LDAP · تم دارک/لایت و ۱۳ زبان · Docker چندمعماری (GHCR)

## ۲. بزرگ‌ترین شکاف: عقب‌ماندگی از آپستریم PHOENIX (v3.3.1 → v3.10.2)

PHOENIX روی **PHOENIX v3.3.1** قفل است؛ آپستریم اکنون روی **v3.10.2 (اکتبر ۲۰۲۶)** است. یعنی همهٔ امکانات v3.4 تا v3.10 را نداریم:

| قابلیت | نسخهٔ آپستریم | توضیح |
| --- | --- | --- |
| **HWID / محدودیت دستگاه** | v3.4–v3.7 | سقف دستگاه per-client، حذف تک‌دستگاه، endpoint وضعیت اسلات HWID |
| **TUIC v5 بومی** | v3.8 / v3.9 | سرور TUIC داخل پنل (Go) با BBR، UDP relay بومی، حسابداری ترافیک crash-safe، لینک `tuic://` و خروجی Clash |
| **MASQUE** | v3.10 | پروتکل و ترنسپورت MASQUE برای inbound/outbound + WARP روی MASQUE |
| **XDRIVE** | v3.10 | تونل زدن ترافیک روی فایل‌های Google Drive / پوشهٔ محلی / هر API ذخیره‌سازی HTTP |
| **ربات Discord** | v3.8 | آینهٔ اعلان‌های تلگرام با تب تنظیمات اختصاصی |
| **تمدید تقویمی** | v3.7 / v3.9 | تمدید در روز ثابت ماه/هفته + پیش‌نمایش برنامهٔ تمدیدهای بعدی |
| **چرخهٔ ریست ترافیک per-client** + سقف تعداد تمدید خودکار | v3.7 | به‌جای ریست سراسری inbound |
| **بات تلگرام: سطح دسترسی، لینک دعوت، Broadcast** | v3.9 | قفل حساب‌های ناشناس، self-service با لینک دعوت، ارسال پیام همگانی به همهٔ کلاینت‌ها |
| **کنترل‌های ساب** | v3.8 / v3.9 | `excludeFromSub` (مخفی‌سازی اینباند از ساب بدون غیرفعال‌کردن)، متغیرهای `PROTOCOL`/`TRANSPORT`/`SECURITY` در remark، User-Agent برای ساب‌های خارجی، انتقال شمارندهٔ ترافیک موقع import/export |
| **Command Palette (Ctrl+K) و PWA نصب‌شدنی** | v3.7 / v3.8 | |
| **MTProto چندکاربره (mtg-multi)** | v3.5 | FakeTLS per-client، ad-tag per-client، کوتا/انقضای per-client در sidecar، hot-apply |
| **مقیاس‌پذیری ۵۰۰هزار کلاینت** | v3.5 | lookupهای batch، WebSocket delta، ساب از جدول‌های نرمال‌شده |
| **امنیت و عرضه** | v3.8–v3.10 | چرخش توکن API با scope/انقضا، sandbox systemd، SHA-256 برای نصب‌کننده، مسیرهای ساب رندوم، SBOM/provenance |
| **کیفیت‌های ریز** | v3.4–v3.10 | سرعت لحظه‌ای per-client، تست تأخیر واقعی خروجی‌ها، egress IP+کشور، جستجو/مرتب‌سازی جدول‌ها، بازطراحی viewer لاگ، کانال آپدیت dev-latest، انتقال کامل SQLite→PostgreSQL |

> نکته: PHOENIX خودش AmneziaWG بومی و MTProto دارد، ولی نسخه‌های آپستریم این دو (AWG 3.1 با embedded userspace device در v3.7+، MTProto چندکاربره در v3.5+) ویژگی‌هایی دارند که نسخهٔ فعلی PHOENIX فاقد آنهاست.

## ۳. پاسارگارد (PasarGuard) — چیزهایی که دارد و PHOENIX ندارد

| قابلیت | وضعیت در PHOENIX |
| --- | --- |
| **مدل کاربرمحور (User = چند پروتکل با یک هویت)** به‌جای کلاینت-در-اینباند | ❌ مدل PHOENIX (مثل PHOENIX) client-per-inbound است |
| **گروه‌ها (Groups)** برای کنترل دسترسی کاربر به هاست‌ها/اینباندها | ❌ فقط برچسب `Group` روی کلاینت داریم |
| **هاست‌های هوشمند چندمقداری** — لیست‌های SNI/host/address با انتخاب **رندوم در هر درخواست ساب**، wildcard با salt رندوم، متغیرهای قالب ({USERNAME}، {SERVER_IP}، {PROTOCOL}...)، **ECH config**، فیلتر هاست بر اساس **وضعیت کاربر**، اولویت‌بندی | ⚠️ هاست داریم ولی نه با این سطح هوشمندی/رندوم/ECH |
| **User Template (تمپلیت پلن)** برای ساخت سریع کاربران با تنظیمات مشترک | ❌ |
| **وضعیت On-hold** (شروع اعتبار از اولین اتصال / مهلت فعال‌سازی) | ❌ |
| **Revoke Subscription** (باطل‌کردن لینک ساب قبلی و صدور لینک جدید) | ❌ |
| **خروجی‌های ساب Sing-box و Outline** (علاوه بر V2Ray/Clash/ClashMeta) | ⚠️ فقط raw/JSON/Clash |
| **محدودیت HWID/دستگاه** | ❌ |
| **محدودیت ترافیک دوره‌ای (روزانه/هفتگی/ماهانه) به‌شکل استراتژی** | ⚠️ ریست دوره‌ای بر مبنای روز داریم، نه استراتژی‌های منعطف |
| **RBAC چند ادمین با دسترسی‌های granular** | ❌ فقط ادمین + نماینده |
| **CLI کامل** (ساخت owner، نمایش نسخه، ...) | ⚠️ منوی `phoenix` داریم، CLI مدیریتی API-محور نه |
| **مانیتورینگ سرویس و نودها** (سلامت، CPU/RAM، آپ‌تایم، تفکیک کشور) | ⚠️ متریک‌ها و وضعیت نود هست، «Service Monitoring» مجزا نه |
| **عملیات گروهی (Bulk) پیشرفته** | ⚠️ bulk add/attach/detach/adjust داریم؛ انتخاب‌های گروهی پیشرفته‌تر نه |
| **مالکیت مشترک نودها، صف مصرف پایدار، جلوگیری از دوباره‌شماری** (در برخی توزیع‌ها) | ❌ |

نکتهٔ مثبت دربارهٔ پاسارگارد: طبق گزارش‌های دسامبر ۲۰۲۵ (IRCFS) نگرانی‌های امنیتی/حریم خصوصی (ارسال IP و توکن به endpoint دانیت) دربارهٔ آن مطرح شده — یعنی از نظر اعتماد، PHOENIX موقعیت بهتری دارد؛ شکاف‌ها فنی/محصولی است نه اعتباری.

## ۴. PHOENIX (آپستریم MHSanaei) — همان بخش ۲

چون PHOENIX خودش فورک PHOENIX است، «PHOENIX دارد و ما نداریم» دقیقاً یعنی **شکاف نسخه‌ای v3.3.1 → v3.10.2** که در بخش ۲ فهرست شد. مهم‌ترین‌ها به‌ترتیب اثر کاربری:
1. HWID (فروشندگان اکیداً می‌خواهند)
2. TUIC v5 + MASQUE (پروتکل‌های نسل جدید ضدفیلتر)
3. تمدید تقویمی + چرخهٔ ریست per-client (حیاتی برای فروش اشتراکی)
4. ربات Discord + Broadcast تلگرام
5. کنترل‌های ساب (`excludeFromSub`، متغیرهای remark، انتقال ترافیک)

## ۶. مرزبان (Marzban) — چیزهایی که دارد و PHOENIX ندارد

| قابلیت | وضعیت در PHOENIX |
| --- | --- |
| **مدل کاربرمحور**: یک کاربر، یک لینک ساب، همهٔ پروتکل‌ها | ❌ |
| **وضعیت‌های کاربر**: active / on_hold / limited / expired / disabled | ❌ وضعیت on_hold/limited مجزا نداریم |
| **On-hold**: شروع اعتبار از اولین اتصال + مهلت فعال‌سازی (`on_hold_timeout`, `on_hold_expire_duration`) | ❌ |
| **استراتژی ریست ترافیک**: no_reset / day / week / month / year | ⚠️ `Reset` (روز) + ریست دوره‌ای داریم، نه این استراتژی‌ها |
| **فیلدهای کاربر**: `note`، `sub_last_user_agent`، `online_at`، تاریخ آخرین آپدیت ساب | ❌/⚠️ |
| **مالکیت کاربران توسط ادمین‌ها (owner) و ادمین sudo** | ⚠️ نمایندهٔ ما قوی‌تر است ولی «چند ادمین با مالکیت» نه |
| **نودهای سبک (Marzban-node)** با همگام‌سازی مرکزی کاربران | ⚠️ نود PHOENIX داریم (بین پنل‌ها) |
| **صفحهٔ ساب کاربرپسند** (نوار مصرف، روزهای باقیمانده، کپی یک‌کلیکی) | ⚠️ صفحهٔ اطلاعات داریم، ساده‌تر |
| **API-first + CLI کامل** | ⚠️ API داریم؛ CLI کامل نه |
| **تمپلیت کاربر** (نسخه‌های جدید) | ❌ |

نکته: PHOENIX برتری‌های روشنی نسبت به مرزبان دارد: تنوع پروتکل (WireGuard/AWG/OpenVPN/L2TP/Hysteria/MTProto در برابر فقط VMess/VLESS/Trojan/SS)، دسترسی کامل به Xray (روتینگ/بالانسر/خروجی‌ها)، و سیستم نمایندگی فروش. شکاف‌های بالا بیشتر مدل داده و تجربهٔ فروش اشتراکی است.

## ۷. novaX (NOVA-X-PANEL) — چیزهایی که دارد و PHOENIX ندارد

novaX عملاً فورک rebrand‌شدهٔ PHOENIXِ جدید با ظاهر شیشه‌ای (Glass UI) است:

| قابلیت | وضعیت در PHOENIX |
| --- | --- |

| **AmneziaWG بدون ماژول کرنل** (userspace) | ⚠️ AWG بومی خودمان را داریم — مقایسه مستقیم لازم است |
| **TUIC v5 sidecar با BBR و 0-RTT** | ❌ |
| **کلاینت ویندوز اختصاصی NOVA-V2RAYN** (تم اختصاصی، ping لحظه‌ای، ECH و Clean IP، Xray + sing-box) | ❌ **PHOENIX اصلاً اپ کلاینت اختصاصی ندارد** — بزرگ‌ترین تفاوت محصولی |
| **ظاهر Glass UI اختصاصی** | ⚠️ برندینگ PHOENIX داریم، طراحی متمایز نه |

## ۸. اشاره به بقیه («و ...»)

- **Marzneshin** (فورک پیشرفتهٔ مرزبان): مدل Service/Node/Host ازهم‌جدا، سیستم سرویس‌ها و اشتراک‌ها، گروه‌های کاربری، پنل مدرن‌تر — الهام‌بخش مدل کاربرمحور.
- **Remnawave**: داشبورد مدرن TypeScript، نود اختصاصی، SDK، تمپلیت‌ها، تمرکز بر UX فروش.
- **V2Board / سیستم‌های فروش**: پرداخت آنلاین (درگاه)، تیکت، پلن‌های فروش، صفحهٔ خرید — چیزی که هیچ‌کدام از پنل‌های Xray-محور (از جمله PHOENIX) ندارند و در بازار ایران مکمل پنل است.

## ۹. جمع‌بندی: نقشهٔ راه پیشنهادی برای PHOENIX

### فوری (بیشترین اثر روی فروش/کاربران) — ✅ تکمیل‌شده (`v4.1.0-omega` .. `v4.1.1-omega`)
1. ✅ **HWID / محدودیت دستگاه** — خواستهٔ رایج فروشندگان؛ در PHOENIX، پاسارگارد و novaX هست (`v4.1.0-omega`).
2. ✅ **شروع اعتبار از اولین اتصال (on-hold / first-use) + مهلت فعال‌سازی (`activateBefore`)** (`v4.1.0-omega`).
3. ✅ **تمدید تقویمی + چرخهٔ ریست ترافیک per-client + استراتژی ریست (روزانه/هفتگی/ماهانه)** (`v4.1.0-omega`).
4. ✅ **خروجی‌های بیشتر ساب: Sing-box و Outline** + متغیرهای بیشتر remark + `excludeFromSub` (`v4.1.1-omega`).

### کوتاه‌مدت — ✅ تکمیل‌شده (`v4.2.0-omega` .. `v4.4.0-omega`)
5. ✅ **پورت قابلیت‌های آپستریم v3.5–v3.10**: TUIC v5 (`v4.4.0-omega`)، MASQUE (`v4.3.5-omega`)، XDRIVE (`v4.3.4-omega`)، ربات و وب‌هوک Discord (`v4.3.3-omega`)، Broadcast تلگرام (`v4.2.1-omega`)، Command Palette (`v4.3.1-omega`)، امنیت توکن‌ها (`v4.3.0-omega`).
6. ✅ **تکمیل ربات تلگرام**: اعلان‌های پیش‌از اتمام (`v4.2.0-omega`)، گزارش دوره‌ای (`v4.2.3-omega`)، لینک دعوت self-service (`v4.2.2-omega`)، broadcast (`v4.2.1-omega`).
7. ✅ **SSL یک‌کلیکی + تمدید خودکار** (Let's Encrypt داخلی RFC 8555 + Self-Signed) (`v4.3.2-omega`).

### میان‌مدت (تمایز محصولی) — ✅ تکمیل‌شده (`v4.5.0-omega` .. `v4.5.4-omega`)
8. ✅ **RBAC چند ادمین واقعی** با دسترسی granular (`superadmin`, `admin`, `support`, `viewer`) + محدودیت ماژول‌ها (`v4.5.1-omega`).
9. ✅ **تمپلیت پلن (User Template)**، **ابطال/چرخش لینک ساب (Revoke Sub)** و **هاست‌های هوشمند چندمقداری/رندوم/وایلدکارد (`*.domain.com`)/تمپلیت (`{USERNAME}`)** (`v4.5.0-omega`).
